# alylabb Reels harness

Первая версия самостоятельной студии Reels для Альмиры. Код хранится в GitHub,
приложение работает локально на macOS или на собственном Linux-сервере.

## Рабочий процесс

1. Добавить референсы и авторские заметки. Для анализа речи и кадров загрузить видеофайл.
2. Создать выпуск с заданием и вопросами аудитории.
3. Получить сценарий, варианты хука, список проверяемых утверждений и раскадровку каждой секунды.
4. Утвердить сценарий. Выбрать собственную съёмку, аватар HeyGen или смешанный режим.
5. Загрузить записи или дождаться HeyGen. При необходимости сгенерировать отдельную видеовставку.
6. Подготовить монтажный план с нарезкой исходников, субтитрами и анимированными карточками.
7. Собрать MP4 1080×1920, посмотреть результат, утвердить видео.
8. Указать будущую дату и публичную постоянную HTTPS-ссылку на этот MP4, запланировать Reels через Metricool.

Согласование сценария предшествует выбору способа съёмки. Генерации и публикации
запускаются отдельными действиями пользователя. Внешние запросы расходуют средства API.

## Запуск на Mac через Docker

Понадобятся Git и Docker Desktop с запущенным Docker Engine.

```sh
git clone https://github.com/Almira8/harness.git
cd harness
cp .env.example .env
```

Заполнить `OPENAI_API_KEY` в локальном `.env`. Остальные подключения можно добавить позже.

```sh
docker compose up --build -d
```

Открыть http://localhost:8000. Первая сборка скачивает зависимости и Chromium.
Без ключей доступны создание выпусков, референсы и импорт сценариев и монтажных планов.

```sh
docker compose logs -f worker
docker compose down
```

`down` сохраняет базу и исходники. Для обновления кода использовать `git pull`,
затем `docker compose up --build -d`. Перед обновлениями сохранять резервную копию.

## Запуск без Docker

Нужны Python 3.11+, Node.js 22+, FFmpeg и FFprobe в PATH.
Для распознавания надписей в видеореференсах установите Tesseract с языками
`rus` и `eng`. В Docker оба языка уже входят в образ.

```sh
cp .env.example .env
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm --prefix renderer ci
cd renderer
npx remotion browser ensure
cd ..
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором окне Terminal из корня проекта запустить worker.

```sh
.venv/bin/python -m app.worker
```

В этом режиме по умолчанию используется SQLite в `data/harness.db`.
Docker Compose использует PostgreSQL. Для перехода между ними понадобится перенос данных.

## Подключения

| Переменные | Назначение |
| --- | --- |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Генерация сценария, исследование, визуальный анализ и монтажный план |
| `TRANSCRIPTION_MODEL` | По умолчанию `whisper-1` с таймкодами сегментов |
| `HEYGEN_API_KEY` | Доступ к HeyGen API и генерация видеовставок |
| `HEYGEN_AVATAR_ID`, `HEYGEN_VOICE_ID` | ID собственного образа и выбранного голоса |
| `HEYGEN_ENGINE` | Поддерживаемый образом движок. По умолчанию `avatar_iv` |
| `METRICOOL_TOKEN`, `METRICOOL_USER_ID`, `METRICOOL_BLOG_ID` | Доступ к календарю Instagram. Указан brand ID 8265789 |
| `MEDIA_BASE_URL` | Адрес API, доступный процессу рендера. Compose задаёт `http://api:8000` |

После изменения `.env` перезапустить оба процесса. Ключи остаются на сервере.
Подключения ChatGPT автоматически не передают доступ отдельному серверу.
Тариф и доступ каждого API необходимо проверить в своём аккаунте.

## Что реализовано и что предстоит проверить

Реализованы долговечная очередь, история сценариев и правок, согласования, загрузка
видео, расшифровка, анализ шести кадров, структурированные сценарии и монтажные планы,
Remotion-рендер с нарезкой, плавными укрупнениями, четырьмя типами анимации карточек
и субтитрами. Есть адаптеры HeyGen v3 для аватара и видеовставок и Metricool для
планирования и чтения статуса. Источники и лимиты внешних API приведены ниже.

Полный цикл внешних API требует ключей и собственных материалов. Качество
сценариев, синхронизации и художественного монтажа проверяется на первом реальном выпуске.

- Исследователь использует веб-поиск. Полный сбор Reels по РФ и точные данные об аудитории
  чужих роликов требуют отдельного источника данных. Без метрик агент сообщает ограничение.
- Ссылки Instagram сохраняются как источники. Автоматическое скачивание закрытых роликов
  не реализовано. Для анализа нужны загруженные файлы.
- Анализ шести кадров даёт выборочную оценку композиции. Он не восстанавливает все переходы.
- Текущий монтажёр создаёт план для поддерживаемых компонентов Remotion. Генерация произвольного
  кода анимации, сложная графика, автоматическое отделение человека от фона и точная работа
  с жестами относятся к следующему этапу.
- В первой версии музыка и SFX описываются в раскадровке. Автоматическое добавление
  отдельных музыкальных и звуковых дорожек пока не реализовано.
- Для Metricool нужен публично доступный готовый MP4. Локальный файл можно скачать
  и разместить в своём хранилище. Автоматическая выгрузка в объектное хранилище пока не подключена.
- Статус публикации запрашивается из панели. Регулярное расписание выпуска,
  автоматический сбор аналитики и обратная связь по метрикам — следующий этап.
- Проверка видео после рендера пока техническая. Проверку художественного качества выполняет автор.

## Очередь и восстановление

API сохраняет задания в БД, worker выполняет их отдельно. Частичный уникальный индекс
ограничивает выпуск одной активной задачей. Worker поддерживает heartbeat и помечает
прерванные задачи для проверки. ID запущенного видео HeyGen сохраняется до ожидания.
Повтор получения результата использует тот же ID. После неопределённого результата
внешнего POST автоматическое повторное создание отключено. Перед закрытием такой задачи
проверить кабинет HeyGen или календарь Metricool, чтобы избежать дубля и повторной оплаты.

## Хранение и доступ

Исходники и рендеры находятся в `data/`. PostgreSQL — в Docker volume `postgres_data`.
В Git эти данные и `.env` не включаются. Для резервного копирования сохранить `data/`
и дамп PostgreSQL, например `docker compose exec -T db pg_dump -U harness harness > backup.sql`.

Панель предназначена для одного пользователя и привязана к loopback-интерфейсу.
Для удалённого сервера подключаться через SSH tunnel
`ssh -L 8000:127.0.0.1:8000 user@server`.
Перед публичным доступом потребуется аутентификация и HTTPS reverse proxy.
Публикуйте только выбранные готовые MP4 через отдельное хранилище.

## Проверки разработки

В среде сборки прошли 10 тестов маршрута согласований и очереди, проверка TypeScript
и синтаксиса JavaScript. Экспорт MP4 в этой среде не завершён из-за системного ограничения
`os.networkInterfaces` (`uv_interface_addresses`). Docker-сборка и браузерная проверка
панели также требуют проверки на целевом Mac или сервере. До этого проект следует
считать первой версией для проверки, а не полностью проверенным производственным запуском.

```sh
.venv/bin/pip install pytest
.venv/bin/python -m pytest
npm --prefix renderer run typecheck
```

## Пять этапов для видеореференса

В студии выберите «Референс» и MOV или MP4. Разбор получает отдельные кадры
с таймкодами, включая начало, склейки и выборку по всему ролику, а при наличии
звука — расшифровку. OCR читает надписи на русском и английском. В карточке
выпуска «Текст из референса» показывает распознанную речь и надписи с
таймкодами, а также тему, которую определила студия. Если тему нельзя
подтвердить, укажите её через «Запросить правки». Для выпуска, созданного до обновления, запустите подготовку
сценария заново, чтобы обновить разбор.

После согласования сценария выберите «Мой аватар HeyGen». Для новых запросов
студия использует HeyGen v3 с движком из HEYGEN_ENGINE, единым текстом и фоном
первой сцены (цвет или изображение). Крупности меняются на монтаже. CLI
поддерживает прежнюю мультисценовую генерацию. После рендера «Запросить правки»
передаёт комментарий монтажёру и использует готовую запись аватара. Папка `workspace/<id выпуска>/` на Mac
смонтирована в контейнер worker. Загрузка собственной съёмки, JPEG и старые выпуски
сохраняют прежний маршрут. Для новых видеореференсов UI и CLI используют одни модули.

Из корня проекта с установленными requirements и FFmpeg (libass, libx264, drawtext):

```bash
python main.py --ref path/to/video.mov --bg studio_dark
```

CLI по умолчанию выполняет все пять этапов, включая платный запрос HeyGen.
Чтобы сначала прочитать сценарий, укажите стабильный ID и остановку:

```bash
python main.py --ref path/to/video.mov --job-id pilot --bg studio_dark --until-step 3
python main.py --job-id pilot --from-step 3
python main.py --job-id pilot --only-step 5
```

В Docker используйте `docker compose exec worker python main.py …`; путь к исходнику
должен быть виден внутри контейнера (например, загруженное видео в `/data/uploads/`).
`--from-step 3` читает существующий 3_script_plan.json с ручными правками.
`--only-step 3` заново пишет сценарий по 2_analysis.json. `--only-step N` запускает
ровно один этап. После изменения речи, крупности или фона используйте
`--from-step 3` или `--from-step 4`. После изменения субтитров, плашек или музыки
достаточно `--only-step 5`. Для 16:9 укажите `--aspect 16:9`.

| Этап | Чекпоинты в папке выпуска |
|---|---|
| 1 | preview.mp4, audio.wav при наличии звука, стоп-кадры, contact_sheet.jpg, 1_extracted.json |
| 2 | 2_analysis.json с отдельными полями для смысла, монтажа и транскрипта |
| 3 | 3_script_plan.json со сценами, музыкой и стилем субтитров |
| 4 | Сохранённый ID запроса, 4_render.json и 4_heygen_raw.mp4 |
| 5 | Тайминги слов, remotion_props.json и 5_final_output.mp4 |

### Режимы фона

Из корня репозитория, где `reference.mov` — ваш исходник:

```sh
python main.py --ref reference.mov --job-id preset-demo --bg-mode preset --bg studio_dark
python main.py --ref reference.mov --job-id auto-demo --bg-mode auto_match
python main.py --ref reference.mov --job-id ai-demo --bg-mode ai_generate
python main.py --ref reference.mov --job-id green-demo --bg-mode remotion_greenscreen
```

- `preset` применяет один пресет ко всем сценам. Для новых выпусков по умолчанию
  используется `studio_dark`.
- `auto_match` выбирает пресет по смыслу каждой сцены. `--bg` задаёт запасной
  вариант на случай, если сценарист предложит неизвестное имя.
- `ai_generate` генерирует кадр каждой сцены через OpenAI Image
  (`BACKGROUND_IMAGE_MODEL`, по умолчанию `gpt-image-1`). PNG сохраняются как
  `workspace/<job_id>/bg_scene_1.png`, `bg_scene_2.png` и далее. Размер PNG
  1080×1920 или 1920×1080 при `--aspect 16:9`. Явный выбор режима включает
  платные запросы генерации на этапе 4.
- `remotion_greenscreen` подбирает пресет для каждой сцены, отправляет
  `#00FF00` в HeyGen и подставляет фоны на этапе 5. Фон плавно приближается
  отдельно от аватара. Локальные MP4 зацикливаются без звука. Для хромакея
  избегайте зелёного в одежде и предметах аватара.

Справка доступна через `python main.py --help`. Чтобы сначала просмотреть
сценарий, добавьте `--until-step 3`, а затем продолжите с тем же `--job-id`
через `--from-step 4`. Режим сохраняется в `job.json`. При переходе на
автовыбор или хромакей у существующего выпуска заново выполните этап 3
(`--only-step 3 --bg-mode auto_match` или `remotion_greenscreen`), затем
запустите этапы 4 и 5. Для замены конкретного пресета достаточно этапа 4.
В Docker укажите путь, видимый контейнеру, и используйте
`docker compose exec worker python main.py …`.

Стиль редакции задаётся в `config/brand_voice.md`. Чтобы добавить свой фон,
положите файл в `assets/backgrounds/` и добавьте запись в `config/backgrounds.json`:

```json
{
  "my_office": {"type": "image", "path": "assets/backgrounds/office.png", "description": "Светлый офис"},
  "my_loop": {"type": "video", "path": "assets/backgrounds/loop.mp4", "description": "Мягкая динамика"},
  "my_color": {"type": "color", "value": "#20352F"}
}
```

Для локальных JPG, PNG и MP4 идентификаторы HeyGen кэшируются между выпусками
в `data/work/heygen-backgrounds/` по содержимому файла и подключению. Замена
файла автоматически создаёт новую запись. Если используете Docker, пересоберите
контейнеры после добавления локальных фонов. Музыка по-прежнему берётся из `config/`.
Поле `b_roll_query` служит заданием для подбора перебивки.

При сетевой ошибке после отправки видео проверьте историю HeyGen.
Если в heygen-*.json осталось submitting, восстановите подтверждённый video_id
из кабинета перед продолжением. При сохранённом ID ожидание продолжается без нового POST.
Длительности сцен в предпросмотре сценария оценочные; субтитры и финальные переходы
рассчитываются после синтеза речи. Склейки определяются по визуальному порогу FFmpeg.

### Финальный монтаж в Remotion

В Docker зависимости TypeScript и headless Chrome устанавливаются при сборке. Для прямого
запуска на Mac установите зависимости один раз:

```bash
(cd remotion-studio && npm ci && npx remotion browser ensure && npm run typecheck)
```

На первом запуске шага 5 Whisper расставляет слова, затем EditDirector сопоставляет их
со сценами. Положите свои изображения или видео в workspace/<job_id>/broll/ до подготовки
плана и используйте осмысленные имена файлов. Директор получает имена, длительности и
b_roll_query; он может выбрать подходящий файл или пропустить перебивку. Музыка берётся
из поля music.asset в плане сцен. Уровень автоматически ограничивается 0.12.

Для правок плашек, зумов, перебивок и таймингов редактируйте remotion_props.json.
src задаётся относительно папки выпуска. Можно также менять слои и шрифты в
remotion-studio/src/Studio.tsx. Пересборка готового выпуска:

```bash
python main.py --from-step 5 --job-id pilot
# При запуске из Docker:
docker compose exec worker python main.py --from-step 5 --job-id pilot
```

При наличии props эта команда сразу запускает Remotion без обращений к API.
В Docker папка remotion-studio/src подключена к worker: изменения React-кода видны при следующем рендере.
MP4 обновляется после успешного рендера, а копии медиа в public/assets/<job_id> удаляются.
Исходники и правки в workspace сохраняются. Для нового режиссёрского плана сохраните
резервную копию remotion_props.json и уберите этот файл перед повторным запуском шага 5.
